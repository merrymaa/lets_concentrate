# Структура проекта
Приложение логически делится на три слоя: база данных, серверная логика (бэкенд) и пользовательский интерфейс (фронтенд).

## База данных (БД)

Users (Пользователи):

id (уникальный номер);

username (логин);

email;

hashed_password (пароль никогда не хранится в открытом виде!);

created_at (дата регистрации).

Statistics (Статистика):

id;

user_id (чей это результат — связь с таблицей Users);

focus_time_sec (время концентрации в секундах за сеанс);

session_date (когда была тренировка);

timer_type (например, «Помодоро», «Цикличный»);

notes (заметки пользователя о самочувствии).


## Backend (FastAPI)

app/core/: настройки безопасности, секретные ключи.
app/api/: роутеры (эндпоинты). Отдельно /auth (регистрация/вход), /stats (запись статистики), /users.
app/db/: подключение к базе и модели SQLAlchemy (описание таблиц на языке Python).
app/schemas/: модели Pydantic. Это описание форматов данных, которые принимает и отдает API (безопасное зеркало ваших таблиц БД).
main.py: точка входа, где собирается всё приложение.

## Frontend (React + Vite)
src/components/: переиспользуемые части интерфейса (кнопки, карточки таймера, поля ввода).
src/pages/: экраны приложения (LoginPage, RegisterPage, DashboardPage со статистикой).
src/services/: функции, которые обращаются к FastAPI (отправка запросов).
src/hooks/: кастомная логика React (например, хук useTimer(), который считает секунды).
App.jsx: главный файл маршрутизации (определяет, какую страницу показать по адресу).


Шаг 2. Бэкенд: Регистрация и авторизация (Auth)

Это самая важная часть. Безопасность прежде всего.

В schemas создайте Token (будет содержать JWT-токен доступа) и схемы UserCreate (для регистрации) / UserRead (для выдачи пользователю его профиля без пароля).

В routers/auth.py напишите эндпоинт /register. Он должен принимать почту и пароль, проверять, нет ли такого пользователя, хешировать пароль (библиотека Passlib) и сохранять в БД.

Напишите эндпоинт /token. Он проверяет введенный пароль, сравнивая его с хешем из БД, и если всё верно — выдает JSON Web Token (JWT). Этот токен клиент будет хранить у себя и показывать серверу при каждом запросе.


Шаг 3. Бэкенд: Статистика

В routers/stats.py создайте защищенный эндпоинт (требующий валидный JWT-токен) для записи результата тренировки POST /stats/. 
Из токена извлекайте ID пользователя, чтобы привязывать статистику именно к нему.

Создайте эндпоинт GET /stats/, который возвращает список всех рекордов текущего пользователя для отображения графиков.

Шаг 4. Фронтенд: Настройка связи с API

В папке src/services/ создайте файл api.js. В нем пропишите базовый адрес вашего сервера (например, http://localhost:8000).

Напишите функцию-обертку для fetch, которая автоматически добавляет заголовок Authorization: Bearer <токен>, если пользователь вошел в систему.

Шаг 5. Фронтенд: Формы и состояние (State Management)

Сделайте страницы Login и Register. При нажатии кнопки вызывайте ваши функции из services/api.js.

Важный момент: когда приходит успешный ответ с JWT-токеном, сохраняйте его в память браузера. Для новичка проще всего использовать Context API (создайте AuthContext) или локальное хранилище localStorage.setItem('token', data.token).

Шаг 6. Фронтенд: Логика таймера (The Core)

Здесь происходит магия JavaScript.

Создайте компонент Timer.jsx. 

Используйте хук useState() для хранения секунд: const [timeLeft, setTimeLeft] = useState(1500) (это 25 минут).

Используйте useEffect(). Внутри него запускайте setInterval(). Каждую секунду он должен уменьшать timeLeft на единицу.

Когда timeLeft достигает нуля, останавливайте интервал (clearInterval), отправляйте данные на ваш бэкенд через POST /stats/ и проигрывайте звук уведомления (объект new Audio()).

Шаг 7. Сборка пазла: Отрисовка статистики

На главной странице сделайте кнопку «Начать тренировку». После завершения таймера обновляйте список статистики.

Для визуализации используйте библиотеку Chart.js (или просто выводите списком время каждого сеанса). Получайте данные через GET /stats/ и передавайте их в компоненты графиков.
